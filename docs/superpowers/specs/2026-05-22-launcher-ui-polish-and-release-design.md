# 主窗口美化、便携版重打包与 Release 发布设计

## 目标

在已经完成分组测量公式展示与测量面板增强的基础上，继续把软件整体观感做完整，并按用户指定顺序完成后续交付：

1. 继续打磨主启动窗口与实时曲线窗口的整体 UI。
2. 基于最新代码重新生成新的便携版。
3. 把改动同步到 GitHub，并发布新的 Release。

本轮重点不是改动采集逻辑，而是把“已能用的实验工具”收口成“更像正式交付软件”的版本。

## 背景

当前状态已经具备：

- 分组测量流程、平均合力统计、三路组内平均值与力矩计算。
- 数学公式展示、结果卡片、状态提示、历史区、导出表格。
- 主窗口已有分页、串口搜索、工具入口、状态栏和日志区。

但仍有两个缺口：

- 主窗口整体仍偏默认工具界面，缺少一个更完整的软件首页与工作台观感。
- 用户明确要求“先继续完成后续 UI 等部分，再打新便携版，再提交并发 Release”。

## 用户确认的边界

- 本轮 UI 范围采用 `B`：主窗口 + 实时曲线窗口都美化。
- 风格继续沿用此前确认的方向：A 为主、B 有明显参与。
  - A：浅色科研仪器风，专业、清晰、可长时间使用。
  - B：工程控制台风，在状态、结果强调和信息层次上更强。
- 发布顺序固定为：
  - 先做 UI 收口
  - 再打新的便携版
  - 最后同步 GitHub 并发 Release

## 设计结论

### 1. 主窗口改成“轻专业工作台”

`app_launcher.py` 中的主窗口不改变功能结构，但要改成更像软件主页的三层布局：

1. 顶部品牌区
   - 软件名、副标题、用途说明
   - 轻量作者/维护者/GitHub 标注
2. 中部工作区
   - 保留现有 `Notebook` 分页结构
   - 每个 tab 内部按“配置 / 连接 / 操作”分组呈现
3. 底部运行区
   - 状态栏更清晰
   - 日志区更像运行控制台，而不是简单文本框

主窗口目标是让用户一打开就能知道：软件能做什么、文件会保存到哪里、下一步从哪里开始。

### 2. 主窗口强调入口和主次关系

主窗口要增强的核心不是“更多控件”，而是更明确的层级：

- 顶部说明比当前更像一个软件头部，而不是普通说明文字。
- `打开 config / logs / videos / output` 做成统一快捷入口条。
- `开始实时曲线采集` 这一类关键动作要明显比辅助按钮更醒目。
- `搜索串口`、配置路径、临时串口设置等区域要分组，减少表单堆叠感。

### 3. 实时曲线窗口继续收口为“仪器控制面板”

`scripts/serial_logger_with_plot.py` 当前已经有测量面板雏形，本轮继续做整体一致性增强：

- 曲线区保持数据优先，但顶部状态、按钮和标题信息统一视觉语言。
- 去皮按钮、状态色、标题层级和测量面板的颜色节奏保持一致。
- 下方分组测量面板继续维持五层结构：
  - 输入层
  - 操作层
  - 状态层
  - 结果层
  - 历史层

### 4. 结果层的主次固定为“卡片先看，公式再看”

结果层继续遵循已经确认的优先级：

- 第一眼先看到关键数值卡片：平均合力、T1/T2/T3、总电流。
- 第二眼看到数学公式与 `M_y / M_x / M / θ` 的计算结果。
- 第三眼查看历史区和导出结果。

历史区仍以摘要为主，不把整套公式全部重复进去，避免信息过密。

### 4.1 Excel 导出必须同步这些结果列

用户已补充确认：界面结果卡片和公式区里展示的关键数据，在导出的 Excel 中也必须有对应列，不能只显示在界面里。

因此分组测量导出至少需要包含以下结果列：

- `总电流`
- `合力平均值`
- `T1平均值`
- `T2平均值`
- `T3平均值`
- `M_y`
- `M_x`
- `M`
- `theta(度)`

要求：

- 界面上展示的关键结果与导出列保持一致。
- 新一轮 UI polish、便携版打包和 Release 发布，都必须基于这个导出一致性前提进行。
- 如果后续新增主窗口或测量面板中的关键结果展示，不得出现“界面有、Excel 没有”的不一致。

### 5. 作者和 GitHub 标注统一成软件式署名

作者信息继续采用常见软件形式，而不是直接写生硬署名：

- 主窗口：作为软件维护信息的一部分出现。
- 测量窗口：作为轻量底部信息和 GitHub 入口出现。

建议统一为类似：

- `Maintained by Chenghang Li`
- `GitHub: github.com/Es777777/485experiment-software-portable`

### 6. 新便携版必须基于这轮 UI 结果重新生成

UI 收口完成后，需要重新执行当前项目已有的便携版打包流程，生成一份新的桌面便携分发目录与对应 zip 产物。

要求：

- 保持现有便携结构不变。
- 保留版本化命名策略。
- 新包内容必须包含最新 UI、测量公式和导出逻辑。

### 7. GitHub 同步与 Release 以“新交付版本”处理

本轮不是只推一个小补丁，而是以“新版可下载交付物”的思路同步：

- 更新分支内容
- 更新或补充 Release 资产
- 确保 GitHub Release 对应最新便携版文件

如果普通 `git push` 仍受网络限制，则继续使用此前已验证可行的 GitHub API / `gh` 路径完成同步，但目标不变：

- GitHub 上的代码内容与本地最终构建一致
- Release 页面能下载到最新便携包

## 受影响文件范围

### 主要代码文件

- `app_launcher.py`
  - 主窗口品牌区、布局层级、按钮主次、日志区和状态区视觉增强
- `scripts/serial_logger_with_plot.py`
  - 曲线窗口上半区和分组测量面板的一致性收口

### 测试文件

- `tests/test_serial_logger_with_plot.py`
  - 继续补 UI 状态、结果显示、入口脚本与相关回归测试
- 如主窗口存在可稳定验证的辅助文案/状态辅助函数，也应补对应测试

### 打包与发布文件

- `build_release.ps1`
  - 如需微调便携版外观资源或构建内容，需同步
- `README.md`
  - 如截图、说明、下载说明受影响，必要时同步
- `README_portable.txt`
  - 如操作说明与 UI 表达变化明显，必要时同步
- `docs/release-notes/...`
  - 发布时补充本轮 UI polish 和新版便携版说明

## 验证要求

### 自动验证

- 现有 `tests.test_serial_logger_with_plot` 全部通过。
- 文档与 release 元数据测试全部通过。
- 脚本入口帮助命令可从仓库根目录正常运行。
- 导出工作簿表头和结果列覆盖界面关键结果字段。

### 人工验证

- 主窗口打开后，能明显看出品牌区、工作区、状态/日志区三层结构。
- 实时曲线窗口中，测量区的结果卡片、上下文提示、公式区和历史区层级清晰。
- 便携版启动后，主窗口与实时曲线窗口都呈现更新后的 UI。

### 发布验证

- 新的便携包存在于本地构建输出目录。
- Release 页面挂载的下载资产是本轮最新包。
- GitHub 上的代码内容与本地最终结果一致。

## 不做事项

- 不重做整个软件的信息架构。
- 不引入新的 GUI 框架。
- 不在本轮增加新的采集协议或新的实验功能。
- 不把主窗口改成复杂导航式平台。

## 完成标准

本轮完成后，应达到以下结果：

- 主窗口看起来像一个正式的软件入口，而不是默认工具集合。
- 实时曲线窗口与分组测量区在视觉上是统一的专业仪器风格。
- 新便携版包含这轮最新 UI 与测量能力。
- GitHub Release 能直接下载到最新版本，并能代表这轮交付成果。
