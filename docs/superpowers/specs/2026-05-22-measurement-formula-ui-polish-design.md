# 分组测量公式展示与界面润色设计

## 目标

在现有 PWM 分组测量面板基础上，补齐力矩相关计算结果展示，并对该区域做一轮低风险界面润色，让软件从“功能可用”提升到“更像正常实验软件”。

本次重点包括三件事：

1. 在分组测量结果区新增 `M_y`、`M_x`、`M`、`theta` 的计算与展示。
2. 用标准数学公式排版展示这些公式，同时显示本组实际数值。
3. 对分组测量面板做专业化视觉增强，并加入常见软件风格的作者/项目标注与 GitHub 地址。

## 背景

当前 `scripts/serial_logger_with_plot.py` 已经实现：

- PWM 分组测量开始/结束/下一组/导出流程。
- 平均合力计算与结果摘要显示。
- 已完成组历史显示与 Excel 导出。

但当前面板仍有两个明显不足：

- 结果区只突出平均合力，尚未显示用户需要的力矩公式与结果。
- 界面主要由默认 `ttk` 控件直接堆叠而成，虽然能用，但视觉上仍偏简陋，不像成熟实验软件。

用户已经确认：

- 公式应放在当前分组测量结果区下方，与现有结果一起显示。
- 整体风格采用“A 为主、B 有明显参与”的混合方案：以浅色科研仪器风为基础，加入工程控制台式的状态感和结果强调。
- 公式必须按数学写法展示，下划线代表数学下标，分数也应采用标准公式排版，而不是普通横排程序字符串。

## 设计结论

### 1. 结果区增加四个新计算量

在当前组结束后，软件立即计算并展示：

- `M_y = 1/2*T_1 + 1/2*T_2 - T_3`
- `M_x = sqrt(3)/2*(T_2 - T_1)`
- `M = sqrt(M_x^2 + M_y^2)`
- `theta = atan2(M_x, M_y)`

其中：

- `T_1`、`T_2`、`T_3` 明确采用“当前组有效采样区间内三路力值的组内平均值”，而不是单个瞬时点值。
- 如果当前实现中的三路力值对应 `weight_ch1`、`weight_ch2`、`weight_ch3`，则按该映射参与计算。
- `theta` 内部继续按照 `atan2` 的标准计算逻辑执行。

### 2. 公式与数值同时展示

本次不是只增加数值列，而是把结果区改成“公式 + 数值”的组合展示。

每个结果项都包含：

- 一条按标准数学记号渲染的公式。
- 一条对应的本组实际计算结果。

目标效果接近实验软件中的计算结果面板，而不是帮助说明文字列表。用户可以同时看到“公式长什么样”和“本组算出来多少”。

### 3. 公式展示采用真正的数学排版

界面中的公式不使用普通 `Label` 直接拼接 ASCII 文本，而是采用可以渲染数学表达式的方式呈现。展示要求如下：

- 下标按数学下标显示，如 `M_y`、`M_x`、`T_1`、`T_2`、`T_3`。
- 幂次按上标显示，如 `M_x^2`、`M_y^2`。
- 分数按标准分式展示，而不是把 `1/2` 当成普通斜杠文本。
- 根号按标准根式展示。
- `theta` 以希腊字母 `θ` 的数学样式展示。

实现上优先选用当前技术栈内可稳定集成的数学公式渲染方案，避免为了排版引入高风险 GUI 依赖。

### 4. 结果布局改成分区卡片式面板

当前分组测量面板调整为四个可读性更强的区域：

1. 参数录入区：`PWM`、`总电流`
2. 操作区：开始测量、结束测量、下一组、导出表格
3. 结果区：平均合力、`M_y`、`M_x`、`M`、`theta`
4. 历史区：已完成组记录

结果区是本次视觉增强重点，应具有更清晰的层次、边界和强调，不再是简单的一行摘要文字。

### 5. 视觉风格采用“科研仪器底 + 控制台强调”

整体视觉方向采用混合风格：

- 主体为浅色、专业、可长时间阅读的科研仪器式界面。
- 局部通过状态条、强调色、结果卡片、主次按钮区分，体现工程控制台风格。

具体策略：

- 保持浅色背景和高对比文字，避免做成沉重的纯深色控制台。
- 对“测量中”“已完成”“已导出”等状态使用更明显的状态色和更稳定的位置。
- 对结果区采用卡片化或信息块化布局，突出关键数值。
- 对主要操作按钮与次要操作按钮做视觉分层，减少默认控件堆叠感。

### 6. 作者与项目标注采用常见软件署名方式

软件中新增轻量信息标注区，而不是生硬放置“作者李承航”五个字。

建议展示信息包括：

- 项目名称或短标题
- 维护者英文或常用署名形式，如 `Maintained by Chenghang Li`
- GitHub 地址或仓库短链接

该区域应采用较低视觉权重，适合作为底部信息栏或侧边附注，不干扰实验操作。

如果当前 Tk 环境支持稳定点击跳转，可将 GitHub 做成可点击入口；若不适合，则先保证地址清晰可见。

## 组件与改动范围

### `scripts/serial_logger_with_plot.py`

- 增加力矩相关计算辅助逻辑。
- 扩展分组测量结果状态与结果文案。
- 重构测量面板布局，使其具备独立结果区和信息标注区。
- 引入数学公式显示组件或公式渲染承载区域。
- 必要时扩展导出列。

### `tests/test_serial_logger_with_plot.py`

- 先增加失败测试，覆盖新增公式计算、结果展示文本/状态、导出列。
- 对 UI 相关逻辑优先测试状态数据和可验证输出，不依赖人工界面检查作为唯一验证手段。

### 导出工作簿

- 在现有分组导出基础上增加 `M_y`、`M_x`、`M`、`theta` 列。
- 保持现有 summary-first、raw-data-after 的总体导出策略不变。

## 数据与展示规则

### 计算时机

- 仅在当前组成功结束后计算一次并刷新结果区。
- 开始测量后、结束前，不显示伪结果。

### 数值显示

- 公式单独显示为数学式。
- 数值结果单独显示，保留适中的小数位。
- `theta` 在界面中优先显示为角度值，便于实验人员读取；内部仍基于 `atan2` 计算。

### 历史区

- 历史区保留精简摘要，不强制把完整数学公式逐条塞入历史列表。
- 历史区可以增加关键结果摘要，但仍以可快速浏览为先。

## 测试与验证

需要验证：

- 四个新增公式的数值计算正确。
- 结束当前组后结果区会更新。
- 导出表格新增对应结果列，且数值正确。
- 现有分组测量流程测试保持通过。
- 界面视觉增强不会破坏现有测量操作顺序和状态更新。

不做事项：

- 不在本次改动中重构整个主窗口或整体软件架构。
- 不为了数学排版引入过重的新前端框架。
- 不把历史区做成复杂报表面板。

## 交付结果

完成后，分组测量面板应具备：

- 更专业的分区布局和视觉层次。
- 一组以标准数学样式展示的力矩公式。
- 与公式并列显示的实际计算结果数值。
- 轻量但正常的软件署名与 GitHub 标注。
- 与界面结果一致的导出列。
